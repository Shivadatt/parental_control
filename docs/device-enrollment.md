# Device enrollment and Device Owner

This app can run in two very different Android privilege states. The UI and the
native bridge must tell them apart; they must never look the same.

| State | How it is obtained | What works |
|---|---|---|
| Normal install (with Device Admin) | Install the APK/Play build and accept the Device Admin prompt | Policies, commands, usage, location, consent and audit. **Package suspension is unavailable.** |
| **Device Owner** (fully managed) | Fresh/factory-reset device provisioned with this app as owner | Everything above **plus** `DevicePolicyManager.setPackagesSuspended()` for app blocking. |

`setPackagesSuspended()` is only legal for a Device Owner (or profile owner in the
managed profile) on API 24+. A normal Play Store installation is **not** a Device
Owner, so the app reports app blocking as `Unsupported` instead of pretending an app
is blocked. There is no root, Accessibility abuse or permission bypass anywhere in
this project.

## Identifiers

- Application ID / package: `com.parentcontrol.parent_control`
- Device admin receiver: `com.parentcontrol.parent_control.ParentControlDeviceAdminReceiver`
- Admin policy resource: `res/xml/device_admin.xml`
- Minimum Android version: API 24 (Android 7.0)

## Option 1: ADB provisioning (test devices only)

Use only a device you own that is **factory-reset or otherwise unprovisioned**, with
no Google account and no other users. `dpm set-device-owner` fails on a device that
has already completed setup.

```bash
# 1. Install the debug or release APK.
adb install -r build/app/outputs/flutter-apk/app-debug.apk

# 2. Provision the installed app as Device Owner. This must run before any
#    account is added to the device.
adb shell dpm set-device-owner \
  com.parentcontrol.parent_control/.ParentControlDeviceAdminReceiver

# 3. Confirm the owner and the active admin component.
adb shell dpm list-owners
adb shell dumpsys device_policy | grep -i "Device Owner\|parent_control"
```

Expected: `dpm list-owners` reports the package as the Device Owner and the admin
component is active. If the command prints `Not allowed to set the device owner
because ... already set` or `... already has accounts`, the device must be factory
reset before retrying. Do not attempt to work around either error.

## Option 2: QR / zero-touch provisioning (managed fleets)

For a managed fleet, use Android Enterprise QR provisioning generated by your EMM
or by the Android provisioning helper. The QR payload must include an APK download
location and checksum controlled by the organization, plus the admin component
above. This project does not generate or host provisioning QR codes, and nothing was
uploaded to a public service.

Provisioning requires a factory-reset device. It is an organization-level action,
not something the app can grant itself.

## In-app steps after provisioning

1. Sign in as the Parent and create/join a family.
2. Sign in as the Child on the child phone. On the **Child device**, open
   **Set up linking** and create a one-time code/QR; on the **Parent device**, open
   **Link a child** and redeem it. The Child approves the incoming request, then
   registers the phone.
3. On the Child device, grant the requested permissions through the official
   Android screens:
   - Usage Access (`Settings > Special app access > Usage access`)
   - Notifications (Android 13+)
   - Location, and background location if the parent enables tracking
   - Camera/microphone only when a consented assistance session starts
4. On a Device Owner device, verify the capability banner shows suspension support
   before expecting app blocking to work.

The parent policy screen shows **Pending acknowledgement** until the Child device
applies the policy and acknowledges the command. Only then may it show **Enforced**.
If the Child is offline, or the APK lacks Device Owner, the parent sees that state;
nothing is silently treated as blocked.

## Recovery and unlink

- **Stop enforcement:** disable the policy in the parent app, or unlink/revoke the
  child device. The Child app restores suspended packages that are no longer
  blocked, including after policy expiry or removal.
- **Stop the guardian service:** the Child app shows whether the visible foreground
  service is running and provides a stop action. Signing out on the Child also
  requests the native stop.
- **Remove Device Owner (test device):**

  ```bash
  adb shell dpm remove-active-admin \
    com.parentcontrol.parent_control/.ParentControlDeviceAdminReceiver
  ```

  This only works while the app is still the owner. A production managed device
  should be deprovisioned through the organization's EMM or a factory reset.
- **Factory reset** always removes Device Owner, the app and all local data. It is
  the last-resort recovery step and must be an explicit owner decision.
- **Credential revocation:** revoking the child device in the parent app invalidates
  its device credential server-side; the guardian service cannot keep uploading or
  polling with a revoked credential. Re-pairing creates a new device identity.
