Baseline inventory: `docs/testing/functionality_inventory/` at checkout `80375f518139bf922bc1b66c998691bee912af44`.

This is a planning document. Every test below is unexecuted. Static inventory classifications are not runtime results.

## Status and evidence rules

- All execution statuses are **NOT TESTED**; actual results are **NOT EXECUTED**.
- `BLOCKED — EXPLICIT OWNER APPROVAL REQUIRED` and `BLOCKED — DEPENDENCY NOT VERIFIED` are recorded in the Approval Gate column; they are not runtime failures.
- No password, token, secret, or environment-file content is recorded.
- A visible control is not proof of behaviour; a static implementation is not runtime PASS.

## Risk definitions

| Risk | Definition |
|---|---|
| **LOW** | Read-only UI navigation, viewing existing data, or non-mutating observation. No persistent account, family, device, policy, or backend changes. |
| **MEDIUM** | Reversible local or application operation. May change a preference or transient state; requires documented restoration or cleanup. Must not affect the preserved Parent/Child QA relationship. |
| **HIGH** | Persistent account, family, pairing, device, policy, permission, or backend state change. Requires explicit owner approval before execution and a documented impact and restoration plan. |
| **DESTRUCTIVE** | Deletes, revokes, unlinks, wipes, resets, rotates, purges, or irreversibly changes identity or data. Always blocked until separate explicit owner approval and requires a specific recovery/restoration plan. |

Existing risk levels are not downgraded to make cases executable.

## Session preservation rule

Existing Parent and Child QA sessions must never be signed out, replaced, invalidated, or modified as part of Phase 6 QA. The current Parent session is the Run 8 baseline and must remain preserved. This rule cannot be overridden by owner approval, a case-level gate, an approval-register scenario, a risk classification, a dependency, a reversible-action claim, or owner-entered credentials. Sign-out execution is **BLOCKED**. Read-only observation of the current session and visible sign-out affordance is permitted. Any future authentication testing that requires a session change is **BLOCKED — SEPARATE ISOLATED AUTHENTICATION ENVIRONMENT AND EXPLICIT OWNER APPROVAL REQUIRED** and must not use the preserved QA accounts.
