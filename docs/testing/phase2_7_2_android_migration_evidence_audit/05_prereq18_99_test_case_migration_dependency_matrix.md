## 1. Executive Overview & Methodology

This report replaces broad, batch-level assumptions with a definitive, test-case-by-test-case technical audit of database migration dependencies for all **99 manual test cases** in HAVEN Parent Control.

Each test case is assigned exactly one mutually exclusive **Primary Migration Dependency Class**:
- **`M0` — NO DATABASE / MIGRATION DEPENDENCY**: Test runs entirely client-side via UI rendering, local device mock state, offline fallback, or hardware self-test without requiring any database or backend schema.
- **`M1` — EXISTING SCHEMA REQUIRED**: Test executes read or write operations against an already-available operational database schema (tables, basic functions, standard RLS), but does NOT require a fresh database or migration replay.
- **`M2` — STATIC MIGRATION INSPECTION REQUIRED**: Test performs source-level inspection of SQL migration DDL, constraint definitions, triggers, or index structures without requiring database execution.
- **`M3` — FRESH DATABASE / CLEAN MIGRATION REPLAY REQUIRED**: Test verifies clean provisioning, multi-tenant RLS isolation between unpolluted accounts, or cascade orphan cleanup that strictly requires an unpolluted baseline.
- **`M4` — RUNTIME SCHEMA VERIFICATION REQUIRED**: Test verifies live dynamic database behavior, specialized RPC execution, trigger pipelines, or destructive table purges.
