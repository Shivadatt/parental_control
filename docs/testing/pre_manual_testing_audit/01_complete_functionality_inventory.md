## 1. Classification & Status Definitions

### 1.1 Category Classifications
- **`PARENT_ONLY`**: Entry points, UI, and business logic accessible exclusively to the Parent role.
- **`CHILD_ONLY`**: Entry points, UI, and business logic accessible exclusively to the Child role.
- **`SHARED`**: Common infrastructure accessible to both roles (authentication, splash, account, settings).
- **`INTERCONNECTED`**: Distributed workflows requiring coordinated actions or state across both Parent and Child devices.
- **`BACKEND_ONLY`**: Server-side capabilities (Edge Functions, SQL cron, migrations) without direct in-app UI.
- **`ANDROID_NATIVE_ONLY`**: Operating-system level services, broadcast receivers, and device-admin capabilities.
- **`UI_ONLY`**: Client-side controls or settings that exist in the UI but lack underlying functional wiring.
- **`SECURITY_OR_PERMISSION`**: Authentication boundaries, input masking, and OS permission management.
- **`SYSTEM_OR_BACKGROUND`**: Background daemon polling, heartbeat presence, and network state caching.

### 1.2 Implementation Status Classifications
- **`IMPLEMENTED`**: Real, traceable logic connecting UI to local controllers and backend where applicable. (Does NOT mean runtime tested).
- **`PARTIALLY_IMPLEMENTED`**: Substantial implementation exists, but core functional outcomes are truncated or broken.
- **`UI_ONLY`**: Visual controls exist and store preferences, but no engine or service consumes them.
- **`BACKEND_ONLY`**: Server-side logic exists without an in-app trigger.
- **`NOT_IMPLEMENTED`**: No functional implementation found in the repository.
- **`BLOCKED_BY_DEPENDENCY`**: Logic exists but cannot execute due to missing prerequisites.
